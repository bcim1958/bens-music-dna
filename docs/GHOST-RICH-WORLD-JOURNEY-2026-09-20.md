# Ghost rich artist world — first full Music DNA journey

Status: DESIGN BASELINE — build from validated H.E.A.T proof, do not redesign the navigation grammar.

## Why Ghost now
H.E.A.T already proved the rich-artist interaction model on iPhone. Ghost is the first deliberately richer journey through that proven grammar: music, artist story, releases, people/personas, taste relation, live context, sources and graph connections.

This is not “a Ghost page”. It is the first complete Music DNA journey that must prove the knowledge layer can remain musical, personal and navigable while becoming much richer.

## Preserve from H.E.A.T
- Three depths: **Kijken → Bladeren → Verdwalen**.
- Guaranteed semantic return path at every depth.
- Music remains the main road; knowledge is a rewarding side path.
- Every click answers something or rewards curiosity; never just opens another menu.
- Spotify is contextual listening evidence where Music DNA makes a musical claim.
- “Waarom hier?” explains the personal/Master relationship.
- Richness must not feel like complexity.
- Mood DNA / Theme DNA / graph relations are optional routes, not mandatory reading.
- “Verras me!” and Ontdek-DNA remain different product purposes.

## Ghost journey v1

### 1. Arrival — Kijken
The first screen must answer within seconds:
1. Who/what is Ghost?
2. What does Ghost sound like in Ben’s Music DNA?
3. Why is Ghost here for Ben?
4. What can I hear immediately?

Required surface:
- real Ghost artist image only — never AI-generated people;
- authentic logo when rights/source allow it, otherwise typographic artist name;
- concise Music-DNA description;
- “Mijn Smaak” relationship/thermometer grounded in actual Music-DNA data, not invented scoring;
- one contextual Spotify entry point;
- “Waarom hier?”;
- calm doors into Story, Music, People/Personas, Live, Connections.

### 2. Music — Bladeren
Purpose: make the knowledge layer audible.
- releases/albums known to Music DNA;
- essential/known tracks and their Music-DNA relations;
- period/release timeline;
- genre/style taxonomy and, where grounded, Mood/Theme routes;
- Spotify links at album/track claims where useful;
- route back to Ghost and to the exact origin that opened Ghost.

### 3. Story — Bladeren
A concise band timeline, not an encyclopedia dump.
- formation/development and major eras;
- changes that matter musically or visually;
- provenance/source layer behind factual claims;
- deeper reading optional.

### 4. People & personas — Bladeren → Verdwalen
Ghost needs an explicit distinction between real people and stage/persona concepts.
- real-person records only when factually sourced;
- persona/stage-character records clearly labelled as such;
- member/role/time relations represented as graph edges;
- a person/persona route may lead to another band/project only when the relation is grounded;
- always preserve Ghost as the return anchor.

### 5. Live — Bladeren
- setlist.fm route/history where useful;
- current tour information only from current reliable sources;
- representative live context, not an unfiltered event dump;
- later: relation between a track in Ben’s DNA and how it appears live.

### 6. Connections — Verdwalen
Connections must be explainable, never random.
Possible grounded axes:
- Master / Band-DNA relation;
- AllMusic genre/style;
- Mood / Theme;
- member/person relation;
- producer/credit;
- country;
- period;
- Ben’s own positive learning/rating history.

Every connection gets “Waarom deze verbinding?” and, where musical, a listen route.

### 7. Sources — optional proof layer
Preferred source classes already accepted for Music DNA:
- official artist source for current/band-authored information;
- AllMusic for durable taxonomy/editorial relationships;
- setlist.fm for live/setlist context;
- Wikipedia as background/reference, not sole authority for contested/current claims;
- relevant current Dutch rock press such as Arrow Lords of Metal, Rockportaal, Lust for Life and Progwereld where appropriate.

The visible journey stays calm; provenance is available as an optional layer.

## Entry and return routes
Ghost must work when entered from:
- an Ontdek-DNA track;
- Music World / artist search;
- a related artist/person/mood/theme connection;
- “Verras me!”;
- later, DNA Express.

The app remembers the semantic origin. “Terug” means return to that origin, not merely browser-history roulette. A persistent Ghost anchor remains available while wandering deeper inside the Ghost world.

## First proof route
Build and test one end-to-end route before expanding breadth:

**Ghost → one representative track → Why for Ben → release/era → person/persona → grounded connection → representative music → back to Ghost → back to origin.**

Success criteria:
- feels like a musical journey, not a database;
- no click maze;
- no invented taste scores or relationships;
- real artist/person photography only;
- musical claims can be heard where practical;
- source/provenance is reachable without cluttering the main road;
- return path survives every depth.

## Build order
1. Reuse H.E.A.T navigation grammar and component logic.
2. Create a Ghost entity/data record with provenance fields; keep unknowns unknown.
3. Research/fill only the factual minimum needed for the first proof route.
4. Build Ghost v1 alongside production — no W39 route changes.
5. Render on iPhone and make the full proof journey.
6. Only after that generalize the artist template for broader rollout.

## Guardrail
Do not use generated substitute portraits, “Ghost-like” people or decorative AI band images. If a suitable real image cannot be sourced/licensed for the prototype, use a neutral visual treatment until a real source is available.
