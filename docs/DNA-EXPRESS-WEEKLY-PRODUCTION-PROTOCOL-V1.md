# DNA EXPRESS — Weekly Production Protocol v1

Date: 2026-09-15
Status: ACTIVE PRODUCTION PROTOCOL — v1

## Purpose
Make Saturday publication repeatable without making DNA EXPRESS visually or editorially templated.

Core principle:
**The production process repeats. The magazine does not.**

Ben is the subscriber/reader. Normal weekly production does not require his pre-publication approval. Editorial feedback is collected after publication and influences later issues.

## Weekly production contract

### Gate 0 — Freeze the issue window
For each issue record:
- issue number and Music-DNA week;
- publication Saturday;
- editorial cutoff;
- latest closed Music DNA / Muziekmeter state that may be used;
- current Ontdek-DNA delivery state;
- source freshness boundary.

No post-cutoff fact may silently determine a retrospective issue.

### Gate 1 — Build the evidence pack
Collect before writing:
- weekly Muziekmeter observations and daily ratings;
- Ontdek-DNA positives/reserve/delivery state;
- playlist-fit signals when available;
- relevant Master / Band DNA / Genre DNA relationships;
- known concerts and local/regional radar;
- current music journalism and official artist/label sources;
- exact-week historical press candidates for Flashback;
- candidate visual-world material: mythology, symbols, objects, places, action, then portraits.

Every factual editorial candidate must carry source/provenance and date. Separate source opinion from fact.

### Gate 2 — Editorial candidate pool
The desk independently creates a ranked pool rather than filling fixed slots mechanically.

Candidate types may include:
- cover/headliner;
- Mijn Week insight;
- current feature;
- Hard & Heavy / Prog / other desk material;
- Band DNA / Genre DNA finding;
- LIVE!;
- Flashback;
- Dieptebom;
- Ontdek DNA / Edelstenenkabinet;
- GEZIEN?;
- Opdracht aan de redactie.

A recurring rubric may be omitted or reduced when the week does not justify it, except where a governing product decision explicitly makes it structural.

### Gate 3 — Autonomous editorial meeting
Music DNA / DNA EXPRESS decides without asking Ben:
- what deserves the cover;
- what can be combined into one stronger story;
- what is merely interesting but not publishable;
- whether a Dieptebom exists;
- what contrast the issue needs;
- which story order creates the strongest reading journey.

Selection criteria:
1. relevance to Ben's actual music world;
2. surprise/discovery value;
3. evidence quality;
4. narrative strength;
5. visual-world potential;
6. diversity of energy/style/time scale across the whole issue;
7. avoidance of an echo chamber.

No target exists for 21× RAAK or for only safe artists.

### Gate 4 — Source lock
Before production copy is treated as canonical:
- verify names, dates, releases, venues, historical claims and quoted/attributed opinions;
- prefer official/primary sources for hard facts where available;
- preserve uncertainty where evidence is incomplete;
- remove any visual-proof text that merely looks factual but was generated without provenance.

Unverified claims are either sourced, rewritten to a verified claim, clearly qualified, or removed.

### Gate 5 — Visual-world research
For every substantial subject ask in this order:
1. What world does this music inhabit?
2. Which symbols/objects/places define it?
3. Which action or physical environment matters?
4. Only then: is a musician portrait editorially useful?

The cover establishes the week's visual weather. Other substantial stories must have their own grammar and may break through that weather.

Do not default to cards, dashboards, CSS geometry, generic portraits or repeated page formulas.

### Gate 6 — Issue score / dramaturgy
Before final page locking, score the complete issue as a reading journey.

Test:
- Does the next spread offer something the previous one did not?
- Are loud/quiet, dark/light, historical/current and personal/world-facing passages varied deliberately?
- Is there a reason to browse non-linearly?
- Would the opening invite Ben to pick it up from the coffee table?

Use the accepted broad arc as a guide, not a rigid template:
**VERLEIDING → ORIËNTATIE → PERSOONLIJK → ONDERDOMPELING → CONTRAST → ENERGIE → HERKENNING → LIVE → TIJDREIS → VERRASSING → BELONING → AFSCHEID.**

### Gate 7 — Build
Build one coherent digital issue:
- canonical masthead: DNA EXPRESS;
- issue/week/year correct;
- contents entry numbers are rubric/editorial navigation numbers, not page numbers;
- chapter jump and exact-position `← TERUG` behavior preserved;
- no permanent website-like navigation;
- no decorative text without editorial function;
- no duplicate teaser/contents machinery;
- source-backed copy only;
- image-led composition before CSS decoration.

### Gate 8 — QA
A regular issue is not ready until:
- editorial/source QA passes;
- navigation passes;
- no known placeholder/generated factual copy remains;
- Mac coffee-table gate passes internally or through an already validated production standard;
- iPhone one-column behavior remains usable;
- iPad behavior has no blocking failure;
- links/routes used in the issue are valid where applicable.

During Editie NUL, Ben may still be asked for a device/visual gate because the production standard itself is under construction. This is a temporary exception.

### Gate 9 — Publish
Normal weekly delivery is a completed issue, not a request for approval.

Target reader notification:
> **Ben, DNA EXPRESS No.xxx ligt voor je klaar.**

Publication status becomes RELEASED / LIVE only after the actual publication route is verified.

### Gate 10 — Learn after publication
Post-publication signals may include:
- what Ben opened first;
- what he lingered on or returned to;
- visual/world preference;
- story surprise/value;
- GEZIEN? response;
- editorial assignment choice;
- explicit comments;
- playlist-fit observations.

These signals inform later issues but do not rewrite the already published issue.

## Saturday repeatability checklist
A Saturday issue is production-safe only when all are true:
- [ ] issue window/cutoff frozen;
- [ ] evidence pack complete enough for editorial selection;
- [ ] cover/headliner selected autonomously;
- [ ] source lock passed;
- [ ] visual worlds assigned;
- [ ] whole-issue dramaturgy checked;
- [ ] production carrier built;
- [ ] navigation/device QA passed;
- [ ] publication route verified;
- [ ] post-publication learning capture available.

## Failure behavior
If a required factual/source/asset dependency cannot be resolved before publication:
- do not invent it;
- substitute a verified story/clue/visual route when editorially sound;
- omit the element if no strong substitute exists;
- do not block an entire issue for a nonessential decorative dependency.

If a structural publication dependency fails, do not claim RELEASED / LIVE.

## Editie NUL application
